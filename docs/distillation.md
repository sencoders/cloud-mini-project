# Task 2: distillation method and limitations

Sequence-level distillation trains a student on text generated by a teacher. Here
phi3.5's exact `teacher_raw` string is the target after `Command: <command>\nJSON: `.
Pythia-70M uses ordinary causal language-model cross-entropy on completion tokens,
including the real end-of-sequence token. Command tokens and padding positions
have label -100 and do not contribute to the loss. The model can still attend to
the command as context. Teacher text is neither manually labelled nor repaired.

Logit-based distillation instead compares the teacher's and student's probability
distributions over tokens, often with a temperature-scaled KL divergence. This
project provides teacher-generated strings through Ollama, not aligned teacher
logits for each student training position. The teacher and student also have
different tokenizers/vocabularies. Consequently the collected Task 1 artifacts
cannot support a direct token-distribution loss; no such loss is implemented.

EleutherAI/pythia-70m is the required approximately 70-million-parameter, English,
Apache-2.0 causal model. Its small size makes full CPU fine-tuning practical and
keeps weights separate from a future service image. It is a pretrained completion
model, not an instruction-tuned command parser, and has limited capacity and
contextual understanding. This controlled eight-intent task is suitable as a
small distillation demonstration; it is not a reliable general voice assistant.

The teacher's mistakes become training targets. Task 1 removed syntactic/schema
and substring violations but did not establish semantic correctness: a slot may
be a substring and still be the wrong slot. Only the first 1,500 cleaned records
are used, and their retained intent distribution can be imbalanced. Training on
formatted JSON can improve syntax without equivalent improvements in full-frame
accuracy. Model outputs that fail validation remain failures, rather than being
replaced with a correct label or a fabricated default. Evaluation uses all 100
provided validation records and reports raw generations separately from optional
lossless JSON extraction. No hidden-test or 95% service-validity claim is made.

Reproducibility is scoped to the pinned code, source revision, exact dataset bytes,
libraries, CPU settings and seed. Two independent 50-example smoke runs produced
identical saved model weights and per-epoch losses on the execution Mac. This does
not establish bitwise reproducibility across different CPU architectures or
PyTorch versions. The actual CPU and runtimes are recorded under results/task2/.
